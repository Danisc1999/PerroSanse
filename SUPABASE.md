# Cómo poner un servidor de verdad a la app

Guía pensada para hacerlo tú mismo, sin saber programar. Una tarde larga, o dos ratos.
Al terminar: las contraseñas dejan de estar en el código, los jugadores entran con su correo de verdad, y las convocatorias, actas y estadísticas dejan de borrarse.

---

## 1. Qué hace falta

Una cuenta en **Supabase** (supabase.com). Es gratis para vuestro tamaño y no pide tarjeta.
Supabase os da tres cosas: el sistema de contraseñas, la base de datos y el almacén de fotos.

Crea un proyecto nuevo. Ponle de nombre `perrosanse`. Elige la región **West EU (Ireland)**, que es la más cercana.

Cuando termine de crearse, ve a **Project Settings → API** y apunta dos datos:
- **Project URL** (algo como `https://xxxx.supabase.co`)
- **anon public key** (una cadena larga)

Esos dos se pueden poner en el código sin problema: no dan acceso a nada por sí solos.
La otra clave que verás, la `service_role`, **no se pone nunca en el código**.

## 3. Poner los candados

Esto es lo que impide que un jugador o un fan modifiquen nada. **No te lo saltes.**

Otra query nueva, pega y ejecuta:

```sql
-- Función de apoyo: ¿el que está entrando es el míster?
create or replace function es_mister() returns boolean as $$
  select exists (select 1 from perfiles where id = auth.uid() and rol = 'mister');
$$ language sql security definer;

-- Activar la protección en todas las tablas
alter table perfiles       enable row level security;
alter table jugadores      enable row level security;
alter table campos         enable row level security;
alter table partidos       enable row level security;
alter table convocatorias  enable row level security;
alter table alineaciones   enable row level security;
alter table actas          enable row level security;
alter table avisos         enable row level security;
alter table publicaciones  enable row level security;
alter table comentarios    enable row level security;
alter table favoritos      enable row level security;
alter table votos_mvp      enable row level security;

-- Todo el mundo que haya entrado puede LEER
create policy leer_jugadores     on jugadores     for select to authenticated using (true);
create policy leer_campos        on campos        for select to authenticated using (true);
create policy leer_partidos      on partidos      for select to authenticated using (true);
create policy leer_convocatorias on convocatorias for select to authenticated using (true);
create policy leer_alineaciones  on alineaciones  for select to authenticated using (true);
create policy leer_actas         on actas         for select to authenticated using (true);
create policy leer_avisos        on avisos        for select to authenticated using (true);
create policy leer_publicaciones on publicaciones for select to authenticated using (true);
create policy leer_comentarios   on comentarios   for select to authenticated using (true);

-- Solo el míster puede ESCRIBIR en lo suyo
create policy admin_jugachores  on jugadores    for all to authenticated using (es_mister()) with check (es_mister());
create policy admin_campos      on campos       for all to authenticated using (es_mister()) with check (es_mister());
create policy admin_partidos    on partidos     for all to authenticated using (es_mister()) with check (es_mister());
create policy admin_alineacion  on alineaciones for all to authenticated using (es_mister()) with check (es_mister());
create policy admin_actas       on actas        for all to authenticated using (es_mister()) with check (es_mister());
create policy admin_avisos      on avisos       for all to authenticated using (es_mister()) with check (es_mister());
create policy admin_publica     on publicaciones for all to authenticated using (es_mister()) with check (es_mister());

-- Cada jugador contesta SU convocatoria; el míster, la de todos
create policy responder_convocatoria on convocatorias for all to authenticated
  using (es_mister() or jugador_id = (select jugador_id from perfiles where id = auth.uid()))
  with check (es_mister() or jugador_id = (select jugador_id from perfiles where id = auth.uid()));

-- Cada uno gestiona sus favoritos, su voto y sus comentarios
create policy mis_favoritos  on favoritos    for all to authenticated using (perfil_id = auth.uid()) with check (perfil_id = auth.uid());
create policy mi_voto        on votos_mvp    for all to authenticated using (votante = auth.uid())   with check (votante = auth.uid());
create policy mis_comentarios on comentarios for insert to authenticated with check (true);

-- Cada uno ve y edita su propio perfil
create policy mi_perfil on perfiles for select to authenticated using (true);
create policy editar_mi_perfil on perfiles for update to authenticated using (id = auth.uid());
```

Con esto, aunque alguien trastee el código de la app desde su navegador, el servidor le dirá que no.

## 5. Conectar la app

En el archivo `backend.js` de la app, sustituye el contenido de las funciones marcadas con `### SUPABASE ###`.

Arriba del todo del archivo, añade:

```js
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2';

const sb = createClient(
  'https://xxxx.supabase.co',   // tu Project URL
  'tu-anon-public-key'          // tu anon public key
);
```

Y cambia las funciones de acceso por estas:

```js
export async function loginMister(pass, email) {
  const { data, error } = await sb.auth.signInWithPassword({ email, password: pass });
  if (error) return { ok: false, error: 'Correo o contraseña incorrectos.' };
  const { data: perfil } = await sb.from('perfiles').select('rol, jugador_id').eq('id', data.user.id).single();
  if (!perfil || perfil.rol !== 'mister') return { ok: false, error: 'Esa cuenta no es de míster.' };
  return { ok: true, rol: 'mister', id: 7 };
}

export async function loginJugador(email, pass) {
  const { data, error } = await sb.auth.signInWithPassword({ email, password: pass });
  if (error) return { ok: false, error: 'Correo o contraseña incorrectos.' };
  const { data: perfil } = await sb.from('perfiles').select('rol, jugador_id').eq('id', data.user.id).single();
  if (!perfil || perfil.rol !== 'jugador') return { ok: false, error: 'Esa cuenta no es de jugador.' };
  return { ok: true, rol: 'jugador', id: perfil.jugador_id, primeraVez: false };
}

export async function loginFan(email, pass) {
  const { data, error } = await sb.auth.signInWithPassword({ email, password: pass });
  if (error) return { ok: false, error: 'Correo o contraseña incorrectos.' };
  return { ok: true, rol: 'fan', id: data.user.id };
}

export async function registrarFan(nombre, email, pass) {
  const { data, error } = await sb.auth.signUp({
    email, password: pass, options: { data: { nombre } }
  });
  if (error) return { ok: false, error: error.message };
  return { ok: true, fan: { id: data.user.id, nombre, email, favoritos: [] } };
}

export async function cambiarPass(nueva) {
  const { error } = await sb.auth.updateUser({ password: nueva });
  return !error;
}
```

Y borra de `backend.js` las líneas `PASS_INICIAL` y `MISTER_PASS`. **Ese es el momento en que las contraseñas dejan de estar expuestas.**

Para los datos, `cargar` y `guardar` pasan a leer y escribir tablas:

```js
export async function cargar() {
  const [jugadores, campos, partidos, actas, avisos, feed] = await Promise.all([
    sb.from('jugadores').select('*').order('id'),
    sb.from('campos').select('*').order('id'),
    sb.from('partidos').select('*').order('num'),
    sb.from('actas').select('*').order('jornada', { ascending: false }),
    sb.from('avisos').select('*').order('id', { ascending: false }),
    sb.from('publicaciones').select('*, comentarios(*)').order('id', { ascending: false })
  ]);
  return {
    jugadores: jugadores.data, campos: campos.data, partidos: partidos.data,
    actas: actas.data, avisos: avisos.data, feed: feed.data
  };
}
```

Y cada cambio que hoy guarda todo de golpe pasa a ser un `sb.from('tabla').upsert(fila)`.

## 6. Fotos

**A. Crea el almacén.** Menú lateral → **Storage → New bucket**, nombre `fotos`, y marca **Public bucket**.

**B. Da permiso para subir.** Marcarlo como público solo permite *ver* las fotos; para que la app pueda *subirlas* hace falta esto. SQL Editor → New query:

```sql
create policy subir_fotos on storage.objects for insert to authenticated
  with check (bucket_id = 'fotos');
create policy actualizar_fotos on storage.objects for update to authenticated
  using (bucket_id = 'fotos');
create policy leer_fotos on storage.objects for select to public
  using (bucket_id = 'fotos');
```

Sin este paso las imágenes se siguen guardando dentro de cada publicación: funciona, pero pesa mucho y el feed va lento. La app te avisa en pantalla si le falta el permiso.


## 6sexies. Avisos push

Los avisos necesitan tres cosas: una tabla donde guardar los dispositivos, un par de claves de firma, y una función en el servidor que haga el envío.

**A. La tabla.** SQL Editor:

```sql
create table if not exists push_subs (
  endpoint text primary key,
  perfil_id uuid references perfiles on delete cascade,
  p256dh text, auth text,
  creado timestamptz default now()
);

alter table push_subs enable row level security;
create policy alta_push on push_subs for insert to authenticated with check (true);
create policy baja_push on push_subs for delete to authenticated using (true);
create policy leer_push on push_subs for select to authenticated using (es_mister());
```

**B. Las claves.** Entra en `vapidkeys.com`, pulsa el botón y te da dos cadenas: una pública y una privada.

- La **pública** se pega en `backend.js`, en la línea `export const VAPID_PUBLICA = '';` (entre las comillas).
- La **privada** NO se pega en ningún archivo. Va en Supabase: **Project Settings → Edge Functions → Secrets**, con el nombre `VAPID_PRIVADA`. Añade también `VAPID_PUBLICA` con la pública y `VAPID_CORREO` con `mailto:` y tu correo.

**C. La función de envío.** Necesita la herramienta de Supabase en tu ordenador. En una terminal:

```bash
npm install -g supabase
supabase login
supabase link --project-ref gzognxciddxijoljcasn
supabase functions new enviar-push
```

Eso crea `supabase/functions/enviar-push/index.ts`. Sustituye su contenido por:

```ts
import webpush from 'npm:web-push@3.6.7';
import { createClient } from 'npm:@supabase/supabase-js@2';

webpush.setVapidDetails(
  Deno.env.get('VAPID_CORREO')!,
  Deno.env.get('VAPID_PUBLICA')!,
  Deno.env.get('VAPID_PRIVADA')!
);

const sb = createClient(
  Deno.env.get('SUPABASE_URL')!,
  Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!
);

Deno.serve(async (req) => {
  const cors = {
    'Access-Control-Allow-Origin': '*',
    'Access-Control-Allow-Headers': 'authorization, content-type'
  };
  if (req.method === 'OPTIONS') return new Response('ok', { headers: cors });

  const { titulo, cuerpo, destino } = await req.json();

  // Elegir a quién le llega: todos, solo jugadores, solo fans,
  // o un jugador concreto (destino = su id en la tabla jugadores).
  let consulta = sb.from('push_subs').select('*, perfiles!inner(rol, jugador_id)');
  if (destino === 'jugadores') consulta = consulta.eq('perfiles.rol', 'jugador');
  else if (destino === 'fans') consulta = consulta.eq('perfiles.rol', 'fan');
  else if (typeof destino === 'number') consulta = consulta.eq('perfiles.jugador_id', destino);

  const { data: subs } = await consulta;
  let enviados = 0;

  for (const s of subs ?? []) {
    try {
      await webpush.sendNotification(
        { endpoint: s.endpoint, keys: { p256dh: s.p256dh, auth: s.auth } },
        JSON.stringify({ title: titulo, body: cuerpo })
      );
      enviados++;
    } catch (e) {
      // Dispositivo caducado: se limpia.
      if (e.statusCode === 404 || e.statusCode === 410) {
        await sb.from('push_subs').delete().eq('endpoint', s.endpoint);
      }
    }
  }
  return new Response(JSON.stringify({ enviados }), {
    headers: { ...cors, 'Content-Type': 'application/json' }
  });
});
```

Y despliégala:

```bash
supabase functions deploy enviar-push
```

**Qué pasa si te quedas a medias.** Sin la clave pública en `backend.js`, el botón de activar avisos pide permiso pero no suscribe. Sin la función desplegada, la app avisa de que falta. En ningún caso se rompe nada.

**iPhone.** Los avisos solo llegan si el jugador ha añadido la app a la pantalla de inicio y la abre desde ese icono. Está explicado en la pantalla «Instalar» de la propia app.

Mientras la tabla no exista, la app usa sus valores por defecto: el recuento de votos, quién va ganando y las medias de notas quedan ocultos hasta que el míster cierra la votación; el resto se ve.

```sql
create table if not exists temporadas (
```

**B. Alta de jugadores desde la app.** Crear cuentas necesita permisos que no pueden vivir en la app, así que lo hace una función del servidor. En una terminal:

```bash
supabase functions new crear-cuenta
notepad supabase\functions\crear-cuenta\index.ts
```

Borra el contenido y pega esto:

```ts
import { createClient } from 'npm:@supabase/supabase-js@2';

const sb = createClient(
  Deno.env.get('SUPABASE_URL')!,
  Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!
);

const PROVISIONAL = 'sanse2026';

Deno.serve(async (req) => {
  const cors = {
    'Access-Control-Allow-Origin': '*',
    'Access-Control-Allow-Headers': 'authorization, content-type, apikey'
  };
  if (req.method === 'OPTIONS') return new Response('ok', { headers: cors });
  const json = (o: unknown, s = 200) => new Response(JSON.stringify(o), {
    status: s, headers: { ...cors, 'Content-Type': 'application/json' }
  });

  // Solo el míster puede dar de alta cuentas.
  const jwt = (req.headers.get('Authorization') || '').replace('Bearer ', '');
  const { data: quien } = await sb.auth.getUser(jwt);
  if (!quien?.user) return json({ error: 'No autorizado' }, 401);
  const { data: perfil } = await sb.from('perfiles').select('rol').eq('id', quien.user.id).single();
  if (perfil?.rol !== 'mister') return json({ error: 'Solo el míster puede crear cuentas' }, 403);

  const { email, jugador_id, nombre } = await req.json();
  if (!email || !jugador_id) return json({ error: 'Faltan el correo o el jugador' }, 400);

  const { data: creado, error } = await sb.auth.admin.createUser({
    email, password: PROVISIONAL, email_confirm: true
  });
  if (error) return json({ error: error.message }, 400);

  await sb.from('perfiles').upsert({
    id: creado.user.id, rol: 'jugador', nombre, jugador_id, pass_cambiada: false
  });
  await sb.from('jugadores').update({ email }).eq('id', jugador_id);

  return json({ ok: true, provisional: PROVISIONAL });
});
```

Y despliégala:

```bash
supabase functions deploy crear-cuenta
```

Mientras no esté desplegada, la app te lo dice y puedes seguir creando las cuentas a mano desde Authentication.

**C. Respuesta desde el aviso.** Los avisos de convocatoria llevan tres botones (Voy / Duda / No puedo). Al pulsarlos se abre la app y guarda la respuesta sola. No hace falta configurar nada: lo maneja `sw.js`.

**D. Horario de silencio.** Entre las 23:00 y las 8:00 la app no manda avisos push, para no despertar a nadie. Lo publicado se guarda igual.
